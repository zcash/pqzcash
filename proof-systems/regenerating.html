Post-Quantum Zcash

Regenerating the study’s numbers

Every number on the PCS frontier page and in the two notes comes from one of three places: a constant in pareto-model.py typed from a paper or a specification; a constant computed by a script in scripts/ from an external checkout; or the model’s own arithmetic. This file says how to redo the first two kinds. Paths are relative to ragu-pcs/.

The page’s figures and claims

python pareto-model.py writes pareto.html, the standalone page, and the same page for the book in four files that the book’s chapter includes and serves: pareto-book.html (the text), pareto.css (scoped to the page and coloured from mdbook’s theme, with the plot and controls kept dark), pareto.js and pareto-data.js. Every figure that the text quotes sits between markers in pareto-template.html, in the two notes, pasta-proof-size.md and zk-fiat-shamir-with-aborts.md, and in the hardware wallets page, hardware-wallets.md, as <!--fig:NAME-->value<!--/fig-->, and the model fills them when it writes the page. A qualitative statement that the model can check is a named claim(name, text, holds) in define_figures(), and the sentence it guards sits between <!--claim:NAME:HASH--> and <!--/claim-->, the hash the first six hex digits of SHA-256 over the claim’s text; a sentence that carries several claims names them with commas. The run fails, and so does the book build, which runs the model, when any of these holds:

  • a figure’s value in a tracked file differs from the model’s;
  • a claim no longer holds;
  • a claim’s hash in a marker differs from its text’s, which means the claim was reworded and the sentence must be read again;
  • a claim has no marker in any file, or a marker names no claim.

Commands:

python pareto-model.py            # write pareto.html; fail on a stale figure or marker, or a failed claim
python pareto-model.py --fill     # also write the current values and hashes back into the tracked files
python pareto-model.py --figures  # list every figure and every claim

A new number in the text gets a fig() in define_figures() and a marker where it is quoted; a qualitative statement that the model can check gets a claim() and a marker around its sentence. --fill prints each changed figure as old → new and each changed claim with its new text, which is the list of sentences to read before committing. A constant that a script computes goes in the model with a comment naming the script and its inputs, as RANK_SUMS_147, WIDTH_SHRINK_147 and WHIR_147 do.

External checkouts

The scripts expect the checkouts and their outputs under work/, which git ignores, or under the directory that RAGU_PCS_WORK names. The tracked outputs are under estimates/. The local changes are patches under scripts/patches/, one directory per repository, numbered in the order they apply as git format-patch names them, and applied with git am. scripts/akita-checkout.sh makes the two Akita checkouts: it clones the pinned revision, initialises the lattice-estimator submodule, and applies 0001 in the clone and 0001 then 0002 in the worktree.

Pedersen-IPA

  • The proof size and the circuit budget (ragu-size-model.py): the component structure is Ragu’s wire format, and the gate and constraint counts are the ones that ragu_pcd’s internal tests pin (crates/ragu_pcd/src/internal/tests.rs at 8109a41c). python ragu-size-model.py prints the checked-in proof, 7,908 bytes, and python ragu-size-model.py budget the budget table. After a Ragu change, read the pinned counts off those tests and update the constants at the top of the size model.
  • The fuse (PEDERSEN_FUSE_SECONDS): in the Ragu checkout, cargo bench -p ragu_pcd --features multicore --bench criterion_fuse, the Merge2 step at the production rank with one worker, on one core, no assembly. The model calibrates the Pedersen prover to it.
  • Tachyon’s circuits (TACHYON_STEPS): apply the patch under scripts/patches/ragu/ with git am to the Ragu worktree at a1395401, copy scripts/tachyon-gates/ to work/gates/ in the Tachyon checkout (its manifest points at ../../crates/tachyon and at the worktree beside the checkout), and cargo run there. It prints each step’s gates and constraints at header 9.
  • Halo 2 (HALO2_SECONDS): Orchard 0.16.0’s benches/circuit.rs proving group with the recipient counts widened, built with rustc 1.100.0 and pasta_curves 0.6.1 with asm; the two-action and sixteen-action times on one thread.

Akita

  • Openings, slopes, rows and the catalog report (AKITA_128, SLOPE[128], ROWS, estimates/): scripts/akita-pasta-estimates.sh builds the patched Akita and runs the rank ladder (pasta-rank.csv), the catalog re-pricing, the re-plans under each pricing override, and the 128-bit width tables for Pallas and Goldilocks. It writes the TSVs and CSVs that estimates/ holds. The catalog security report there is gen_schedule_artifacts --catalog-report over the shipped families, built with the catalog-security feature, as the re-plan scripts run it. The per-K group runs behind the opening tables are not kept under estimates/; the re-plan scripts reproduce them.

  • The 147-bit floor (AKITA_147, SLOPE[147]): scripts/akita-147-pipeline.sh, on the worktree that the checkout script made, regenerates its width tables at 147 bits (hours; SKIP_TABLES=1 resumes), re-sizes the compression cells, rebuilds and runs scripts/akita-147-replan.sh; then python scripts/akita-150-page-inputs.py work/akita-147-out/replan prints the two dicts in the model’s shape. scripts/akita-150-tables.sh writes CSV width tables at a given floor for every modulus, and the Pallas table alone is infinity_width_table --policy Quantum147BitADPS16 --profiles pallas --format csv --profile local-minimum --output ... in the worktree: 5.5 hours with the estimator built without its parallel feature.

  • Rank growth (RANK_SUMS_147): over the weakest instance of each of the catalog report’s 115 schedules, the least module rank that covers its width at each floor, mapped through each variant’s modulus:

    python scripts/rank-scale.py estimates/catalog-security.tsv \
    work/akita-src/crates/akita-params/src/sis/generated_sis_table \
    work/akita-src-150/crates/akita-params/src/sis/generated_sis_table \
    estimates/linf-width-table-goldilocks.csv work/akita-147-out/linf-width-table-147-goldilocks.csv \
    estimates/linf-width-table-pallas.csv work/akita-147-out/linf-width-table-147-pallas.csv

  • Width shrink (WIDTH_SHRINK_147): the median of the 128-bit width over the 147-bit one, per modulus and ring dimension, over the cells where neither width is at the estimator’s search cap and the width falls. The shipped moduli come from the production table’s policy audit at each floor, Pallas and Goldilocks from the CSV tables:

    python scripts/width-shrink.py 147 \
    work/akita-src/crates/akita-params/src/sis/generated_sis_table/policy_audit.csv \
    work/akita-src-150/crates/akita-params/src/sis/generated_sis_table/policy_audit.csv \
    pallas=estimates/linf-width-table-pallas.csv:work/akita-147-out/linf-width-table-147-pallas.csv \
    goldilocks=estimates/linf-width-table-goldilocks.csv:work/akita-147-out/linf-width-table-147-goldilocks.csv

  • The accumulation matrix (LINF_WIDTHS, estimates/linf-accumulation-widths.tsv): the largest width that Akita’s ℓ∞ estimator certifies at each module rank and each bound of the catalog’s ladder, at ring degrees 512 and 1024, for the Pallas, 64-bit and 128-bit moduli at both floors. The 64-bit and 128-bit moduli come from the production tables the estimator writes into akita-params (generated_sis_table/q64.rs, q128.rs, in the pinned checkout at 128 bits and the 147-bit worktree at 147), Pallas from the CSV width tables above; the Goldilocks CSV tables are checked to coincide with the 64-bit modulus’s rows, which the Goldilocks variant reads. The estimator evaluates only the catalog’s own cells, so a bound is rounded up to the ladder:

    python scripts/linf-accumulation-widths.py \
    128 work/akita-src/crates/akita-params/src/sis/generated_sis_table \
        estimates/linf-width-table-pallas.csv estimates/linf-width-table-goldilocks.csv \
    147 work/akita-src-150/crates/akita-params/src/sis/generated_sis_table \
        work/akita-147-out/linf-width-table-147-pallas.csv work/akita-147-out/linf-width-table-147-goldilocks.csv \
    > estimates/linf-accumulation-widths.tsv

  • The hiding padding’s hardness (HIDING_PADDING_ATTACK_BITS, HIDING_PADDING_SWEEP): the pinned lattice estimator in Akita’s third_party submodule, which the checkout script initialises, under Sage, costs every LWE attack on the knapsack-LWE instance behind the hardware wallet’s padding at 5,000 bits and 1,024, 1,385, and 2,048 rows, then sweeps the padding from 3,500 to 6,000 bits at the device’s 1,024 rows, by 250 and by 50 where the floors are crossed, under the ADPS16 quantum model: sage scripts/knapsack-lwe-check.py from ragu-pcs, about an hour.

  • Typed from the paper and the notes: the verifier times (AKITA_VERIFY_MS, Table 16), the terminal’s inner-image coordinates (IMAGE_COORDS, pasta-proof-size.md §6.1), and the mask’s parameters (MASK_*, the zero-knowledge note’s §5).

WHIR, FRI and the limb hybrid

  • The sweeps (estimates/whir-sweep.tsv, estimates/whir-sweep-grind.tsv): the reference binary at 2^17, 2^18 and 2^20 variables over Field256 and Goldilocks3, rates 1/2 to 1/64, maximum proof of work 0, 16, 20 and 24 bits, 128 bits in the Johnson regime, three verifier repetitions:

    target/release/main -l 128 -d 17 -r 3 -f Field256 -p 20 --reps 3

Each run prints Proof size, Average hashes and Prover time, which are the TSV’s proof_KiB, verifier_khashes and prover_ms; first_samples and queries are the first round’s sample count and the sum over rounds from its commit ... samples N lines.

  • The higher floor (WHIR_147): scripts/whir-sweep-147.sh runs the same binary at 128 and 147 bits over both fields at rates 1/2 to 1/8; the model takes the mean ratios.
  • Zero knowledge (ZK_BYTES, ZK_HASHES, ZK_PROVER): Plonky3’s HVZK-WHIR benchmark, RUSTFLAGS="-Ctarget-cpu=native" cargo bench --bench zk_overhead -p p3-whir -- whir_zk_overhead in work/plonky3-src.
  • FRI’s factors over WHIR (1.95 on the proof, 2.07 on the hashes) are the WHIR paper’s measurements, typed.

The 𝔽₂ family

frib_optimizer.py is the tracked port of Ulrich Haböck’s FRI-Binius proof-size optimizer and runs inside the model. Its calibration (FRIB_MEASURED_MS) and Flock’s throughput and shares are typed from the two papers.

BitZ

BITZ_T10 is the paper’s Table 10, typed. The scalings measured with the proof of concept (BITZ_128, BITZ_RATE, BITZ_PHASES) come from scripts/bitz-rerun.sh build, then scripts/bitz-rerun.sh <profile> 25-28 5 for the three profiles: custom:1:4, Table 10’s rate 1/2 at 100 bits; udrg:1:4:128, rate 1/2 at 128 bits in the unique-decoding regime with grinding; and udrg:3:4:128, rate 1/8 at 128 bits. Then python scripts/bitz-summary.py work/bitz-out/rerun/*.log for the table of commit, grand-product, Ligerito and verifier times and proof bytes. scripts/bitz-pcs-sweep.sh and scripts/bitz-overnight.sh are the single-thread and ten-thread sweeps of the same benchmark.

Kishu

BOOL_CHECK holds the Booleanity draft’s measured reduction (prover and verifier times, payloads, the projection’s scan). spike/ models the protocol and is not a source of page numbers.

Akita’s binary groups

BINARY_MEASURED is the Akita development branch’s measurement of a binary-claim opening (LayerZero-Labs/akita#285, scripts/binary-full-size.sh there at 8046b4cd2, the P128 root), typed.

The applications

The recovery circuit’s and the Merkle path’s costs in each arithmetization (RECOVERY_*, RECOVERY_PATH_*, BOOL_*) are derived in the model’s comments from ZIP 2005’s cost section and the arithmetizations’ own gate costs; Tachyon’s nodes are the measured circuits above. Nothing external is needed beyond the gate probe.

CAPSS

CAPSS_* are the CAPSS paper’s Tables 2, 3, and 6, typed; the CAPSS page’s Kishu estimates apply the model’s Poseidon and digit costs to them.

The sampler

MASK_SAMPLE_NS and its companions are scripts/sampler-bench.c’s measurement: build it with clang -O3 -o work/sampler-bench scripts/sampler-bench.c -lm and run work/sampler-bench 22 32 22.9 aes and work/sampler-bench 22 32 on one core of an idle machine on mains, three times each, and take the medians of the whole-path and randomness-alone lines. The aes form needs macOS (CommonCrypto); the ChaCha20 form is portable.

The carry-less multiplication

GF128_MEASURED_NS is scripts/clmul-bench.c’s measurement of a GF(2^128) multiplication by PMULL against the model’s word multiplication: build it with cc -O3 -mcpu=native -DCHAINS=16 -o work/clmul-bench scripts/clmul-bench.c and run work/clmul-bench on one core of an idle Apple Silicon machine on mains; take the GF(2^128) line’s nanoseconds. The chain count sets how many independent multiplications are in flight, and the Goldilocks line is a scalar reference whose own rate is below the page’s 3e9 a second.

The notes’ own tables

The tables in pasta-proof-size.md §3, §3.1, §6.2 and §6.3 are the planner’s figures from estimates/catalog-reprice.tsv and estimates/reprice-*.tsv, which scripts/akita-pasta-estimates.sh writes; the Pedersen figures there are ragu-size-model.py’s. The figures that the model also computes carry markers and refill with --fill.
